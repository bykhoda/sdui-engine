# SDUI — Aurora OS (Qt/QML + Silica) renderer

The third native renderer of the engine. It consumes the **same** platform-neutral
JSON contract as iOS and Android (see [`../spec/`](../spec)) and renders it with
**Qt Quick / Sailfish Silica** on **Aurora OS (ОС Аврора)** — one contract, three
native apps.

> Status: **v0 skeleton — initial renderer.** Pure QML/Silica, no native model.
> Covers the core primitives (stacks, text, button, image, icon, divider, spacer,
> toggle, textfield) and `$token`/`$state`/`$data` binding. The long tail (list
> templates, chart, calendar, clips, async, swipe, the action runtime) is TODO;
> unsupported components degrade to a visible marker, never a crash. **Not yet
> compiled** — it needs the Aurora SDK (unavailable in this repo's CI); the code is
> written to the documented Aurora conventions (Qt 5.6, `Aurora::Application`,
> Silica, ES5).

## Layout

```
aurora/
  ru.auroraos.SduiPlayground.pro        # qmake project (CONFIG += auroraapp)
  ru.auroraos.SduiPlayground.desktop    # launcher entry
  rpm/…spec                             # RPM packaging (verify vs SDK wizard)
  resources.qrc, content-manifest.json  # GENERATED by tools/gen_qrc.sh
  tools/gen_qrc.sh                       # bundles shared content via <file alias=…>
  src/main.cpp                          # Aurora::Application bootstrap
  qml/
    SduiPlayground.qml                  # ApplicationWindow → CatalogPage
    cover/DefaultCover.qml
    pages/CatalogPage.qml               # catalog (same catalog.json)
    pages/ScreenPage.qml                # renders a screen via SduiRenderer
    sdui/SduiRenderer.qml               # recursive type→Silica renderer
    sdui/Tokens.js                      # binding/token resolution (ES5)
```

## How it mirrors iOS / Android

| Contract concern | iOS (`SDUI*`) | Android (`dev.sdui`) | Aurora (QML) |
|---|---|---|---|
| Bindings (`$token`/`$state`/…) | `BindingEngine` | `core/BindingEngine` | `qml/sdui/Tokens.js` |
| Component registry / dispatch | `ComponentRegistry` | `render/ComponentRegistry` | `SduiRenderer` `Loader` switch |
| Primitives | `Builtins` (SwiftUI) | `render/Builtins` (Compose) | `SduiRenderer` (Silica) |
| Screen host | `SDUIScreenView` | `render/SduiScreen` | `pages/ScreenPage.qml` |
| Catalog / nav | `CatalogNavigation` | `CatalogList` | `pages/CatalogPage.qml` |

`vstack` → `Column`, `hstack` → `Row`, `scroll` → the page `SilicaFlickable`,
`text` → `Label`, `button` → `Button`, `toggle` → `TextSwitch`.

## Shared content — one authored copy

The catalog + screens + tokens are **not duplicated here**. `tools/gen_qrc.sh`
generates `resources.qrc` with `<file alias="content/…">` entries pointing at the
single authored copy under `ios/Sources/SDUIPlayground/Content`, so the RPM bundles
byte-identical JSON. Re-run it whenever screens change:

```bash
sh aurora/tools/gen_qrc.sh
```

## Build & run (Aurora SDK)

```bash
# emulator (i486) or device (armv7hl / aarch64)
sfdk -c target=AuroraOS-5.1.3.85-MB2-aarch64 build
sfdk deploy --sdk
# or, inside the Platform SDK:
mb2 -t AuroraOS-i486 build && mb2 deploy --sdk && mb2 run
```

Qt 5.6 constraints the code respects: no `DelegateChooser` (recurse via
`Loader`+`Repeater`), no `required` properties, no QML `enum`, ES5-only JS.
