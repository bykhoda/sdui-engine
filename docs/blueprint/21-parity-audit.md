# 21 · Renderer Parity Audit — iOS (SwiftUI) vs Android (Compose)

> One JSON contract must render **identically** on iOS (`ios/Sources/SDUIRender` +
> `SDUIRuntime` + `SDUICore`) and Android (`android/sdui/src/main/java/dev/sdui`).
> This audit walks all **30 components**, all **24 modifier keys**, all **24 actions**,
> the two `ActionInterpreter`s and the two `BindingEngine`s, and cross-checks the
> **43-screen corpus** (`ios/Sources/SDUIPlayground/Content/screens/*.json`).
>
> `PARITY.md` (generated by `spec/tools/parity.mjs`) tracks *presence* only — it says
> both platforms "support" all 30 components. This audit tracks **behavioral and
> visual fidelity**, which presence-tracking cannot see. Findings below are what a
> user would actually notice.

**Severity key** — **P0** = a visible or behavioral difference a user notices (a
missing screen chrome, a dead button, an inert gesture); **P1** = subtle (wrong
default size/spacing, a missing haptic, a prop honored on one side); **P2** =
cosmetic (default color, shadow, easing).

---

## Executive summary — the systemic patterns

Four cross-cutting themes explain most of the individual rows:

1. **Screen chrome & collapsing scroll are absent on Android.** `SduiScreen.kt`
   renders only `screen.content`; it never reads `screen.title` or
   `screen.scrollBehavior`. iOS renders a (collapsing large-title) nav bar via
   `SDUIScreenView.swift:288` + `ScrollHeader.swift`. **33/43 screens set `title`;
   19/43 set `scrollBehavior`.** This is the single biggest gap and it hits the
   north-star "collapsing scroll identical on 3 platforms" goal head-on.

2. **Layout defaults differ platform-wide.** Stacks/list/grid default to **~8pt**
   spacing on iOS (SwiftUI default) but **0dp** on Android; unstyled text is **~17pt**
   on iOS vs **~14sp** on Android. These are one-line defaults but they shift nearly
   every screen.

3. **Android hardcodes accent colors** (`0xFF0A84FF`, `0xFF5B5BF0`) wherever iOS uses
   `.accentColor`. Systemic across button / slider / progress / rings / datepicker /
   roadmap / chart / clips / swipe. One fix (thread the host accent token into
   `Theme.kt`) closes ~8 rows at once.

4. **Several modifiers and two native-capability actions are unimplemented on
   Android**: `zoomable`, `onDoubleTap`, `hitSlop`, `accessibility`,
   `presentWhen`/`presentStyle` (modifiers) and `requireVersion`,
   `requestPermission` (actions) all silently no-op.

Conversely, the **`BindingEngine`s are essentially identical** (token grammar,
namespaces, chained-ref depth-8 guard, `Condition` evaluation all match), and the
**`ActionInterpreter` control flow** (`sequence`/`parallel`/`condition` + 18 leaf
actions) matches exactly. The contract's *semantics* are sound; the *render surface*
is where drift lives.

Two notable **reversals** of the usual "iOS leads" pattern: the **`clips` reels feed
is fully wired on Android but inert on iOS**, and **`zstack` alignment is honored on
Android but ignored on iOS**.

## Modifier parity — detailed

Chain application order **matches by design**: both apply background *around* padding
(iOS applies `PaddingModifier` before `BackgroundModifier` so the background wraps the
padded content, `Modifiers.swift:27-30`; Android deliberately reorders to
padding-after-background for the same visual, `SduiModifiers.kt:83-99`). `padding`
edge/axis fallback (`horizontal`/`vertical` filling the matching edge pair) matches
(`Modifiers.swift:297-303` ↔ `SduiModifiers.kt:199-213`). `pulse` shorthand/object,
`scale`/`rotation`/`opacity` transform + `animation` curve mapping
(`linear/easeIn/easeOut/spring/easeInOut`) all match.

| Modifier | Status |
|----------|--------|
| padding, background, cornerRadius, material, blur, shadow, opacity, scale, rotation, pulse, animation, ignoresSafeArea, frame, size, presentStyle(default) | **parity** (material/shadow are tuned approximations on Android) |
| `size` `weight` | iOS lacks stack weight (row 16) |
| `presentWhen`/`presentStyle` | **missing on Android** (row 7) |
| `zoomable` | **missing on Android** (row 12) |
| `onDoubleTap` | **missing on Android** (row 13) |
| `hitSlop` | **missing on Android** (row 15) |
| `accessibility` | **missing on Android** (row 14) |
| `onTap`/`onLongPress`/`contextMenu`/`swipe` | present both; press-feel matches; swipe visuals differ (rows 17-18) |

**"Copy JSON" long-press devtool** (`ComponentRegistry.swift:141-162`) is iOS-only.
Intentional dev feature, not a production parity concern (P2/none).

## Action & binding parity

**`ActionInterpreter`** — control flow (`sequence`, `parallel` (both sequential-await,
documented), `condition`) and 18 leaf actions (`navigate`, `dismiss`, `dismissRoot`,
`openURL`/`openDeepLink`, `setState`, `increment`, `refresh`, `showToast`, `delay`,
`scrollTo`, `haptic`, `share`, `preview`, `log`, `analytics`, `custom`, `request`)
are a **faithful 1:1 port**. Binding-resolution helpers (`resolvedString`/`Value`/`Params`)
match. Gaps:

- `requireVersion`, `requestPermission` — **Android missing** (rows 9-10).
- `saveFile` — in the schema's action enum but **unimplemented on both** platforms
  (falls to the "Unhandled" branch). Parity-neutral but a contract hole; either
  implement or remove from the enum. **P2.**
- `preview` — interpreted on both, but the Android reference `SduiHostDelegate` has no
  `preview` UI (default no-op) whereas iOS wires QuickLook. Host-level, not
  interpreter. **P2.**

**`BindingEngine`** — **parity, no divergence found.** `scanToken` grammar, all six
namespaces (`data/token/env/state/params/item`), whole-vs-interpolation split, chained
token-ref following with the depth-8 guard, and `Condition.evaluate`
(`equals/notEquals/exists/not/and/or`, with `exists` treating missing/null/empty as
false) are identical (`BindingEngine.swift` ↔ `BindingEngine.kt`). Minor: iOS exposes
`fillPlaceholders` (request-path `{key}` filling) on `BindingEngine`; the Android twin
lives in the data layer, not the shared engine — verify it exists there. Not a render
concern.

## Prioritized fix list for the lead

**Sprint 1 — the P0s that break whole screens (Android unless noted):**

1. **Screen chrome + collapsing scroll** in `SduiScreen.kt` (`Scaffold` +
   `LargeTopAppBar` + `exitUntilCollapsedScrollBehavior`, reading `title` /
   `scrollBehavior`). Unblocks 33 screens and the signature interaction. *(row 1)*
2. **Layout defaults**: stack/list/grid `spacing` → 8dp, unstyled `text` → ~17sp.
   Two-line change, corpus-wide impact. *(rows 2, 21)*
3. **`presentWhen`/`presentStyle`** modal host in `ComponentRegistry.Render`. *(row 7)*
4. **`icon` fallback**: expand `materialIcon` + host `iconResolver`, stop defaulting
   to a circle. *(row 3)*
5. **`chart` scrub interactivity** (`interactive`/`unit`/`axes` + crosshair + pill +
   haptic). Signature interaction. *(rows 4-5)*
6. **`clips` on iOS**: wire the rail buttons to `ctx.dispatch` — this one is an
   **iOS** fix. *(row 6)*
7. **`list` filter/sort/limit/pagination/empty** in `ListView`. *(row 8)*
8. **`requireVersion` + `requestPermission`** actions + host plumbing. *(rows 9-10)*

**Sprint 2 — the P1 correctness/feel gaps:**

9. Modifiers Android is missing: `zoomable`, `onDoubleTap`, `hitSlop`, `accessibility`.
   *(rows 12-15)*
10. **Systemic accent color** — thread the host accent into `Theme.kt`; closes ~8 rows.
    *(row 35)*
11. iOS fixes: `zstack` alignment (row 11), stack `weight` (row 16), `$state.` prefix
    normalization (row 34).
12. Control fidelity: `textfield` rich props, `disclosure` card, `ticker` live sync,
    `divider` orientation, `image` aspectRatio, `pager` reduce-motion, `calendar`
    UTC→local, selection/page haptics. *(rows 27, 30, 29, 19, 22, 31, 33, 36)*

**Sprint 3 — P2 cosmetic calibration** (progress animation, shadows, gradient
defaults, chart geometry, material tiers, `filecell.previewURL`, `datepicker` live
binding). Batch these against a snapshot-diff harness.

**Housekeeping:** decide `saveFile`'s fate (implement or drop from the schema enum);
fix the stale `DataViz.kt:158` "lines are straight" comment (they're splined now); and
the stale `Roadmap.swift:6-7` "expand on tap" comment (no tap expansion on either).
